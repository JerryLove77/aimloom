# KovaaK 准星实机测试：下午操作手册

## 先看这几句

- 本轮只测 **KovaaK**，不需要安装 CS2 或 VALORANT。
- 测试目标：PNG 能否正常显示、透明背景是否正常、游戏内缩放是否正常、重启后是否保持，以及能否恢复原设置。
- 本包不是安装器，不会自己修改游戏；里面的自动测试通过记录也不代表实机通过。
- 本轮不证明准星与 CS2／VALORANT 完全一致。尤其 CS2 图像仍是静态近似。
- 只使用这次的一个测试包，不要与之前的包混装；不同包的文件名前缀不同。

## 一、电脑上需要准备什么

- [ ] Windows 电脑能正常打开 KovaaK。
- [ ] 已把整个测试 ZIP 复制到 Windows，并完整解压到一个普通文件夹。
- [ ] 解压后能看到 `manifest.json`、`results.json`、`crosshairs` 和本手册。
- [ ] 已安装 PowerShell 7（Windows 自带 PowerShell 5.1 不适用）。
- [ ] 能打开此前验证过的 Windows 配置安装器 `KVKConfig.exe`。

此前测试机使用过 `C:\kvka1\KVKConfig.exe`，但这个路径需要你在电脑上确认。
**如果找不到安装器或程序打不开，先停在这里，把情况或报错截图发给我。**
不要把 Mac 浏览器演示当成安装器，也不要为了测试自行覆盖游戏配置。

建议在桌面建一个 `Aimloom-准星测试记录` 文件夹，放原设置截图、备份和测试截图。
本手册可以用 Codex、VS Code 或记事本打开。

## 二、先记录原来的状态，再退出游戏备份

### 2.1 游戏还开着时

打开准星相关设置，截图并记录：

- 原来选中的准星名称或文件名；找不到名称就保留完整设置截图。
- 原来的游戏准星缩放值；有颜色、透明度、武器覆盖等相关选项，也一起截图。
- 游戏版本、Windows 版本、分辨率、窗口／全屏模式、Windows 显示缩放。
- 本次准备用的训练场景和武器。

找不到某项就写“未知”，不要猜。先保存一张 `00_原设置.png`，再正常退出 KovaaK。

### 2.2 游戏退出后

通过 Steam 的“浏览本地文件”确认游戏目录。此前验证过的结构是：

```text
游戏安装根目录/
└─ FPSAimTrainer/
   ├─ Saved/SaveGames/
   └─ crosshairs/
```

确认目录后，双击解压目录的 **`Run-Test.cmd`**。自动检测不到时，粘贴上面所说的游戏安装根目录。
测试包应放在游戏目录之外的普通盘符路径；不支持网络路径、链接、短文件名或末尾带点／空格的路径。

在菜单输入 **2** 保存基线。脚本会把 SaveGames 和原有准星文件逐字节复制到
`test-records/session-.../baseline/files`，并生成校验清单。记下显示的会话目录，后续都使用同一会话。
每次新建基线会生成独立目录；不要在安装测试准星后再建基线。

这是独立备份，不会修改游戏文件。不要把整份 SaveGames 覆盖回游戏，以免覆盖新成绩。
游戏未退出、文件损坏或路径不安全时，脚本会停止；这不算测试通过。

## 三、核对环境和测试文件

在助手菜单输入 **1**。成功结果中的 `kitFilesVerified` 应为 6，环境报告会保存到 `test-records`。
若有报错、文件缺失或没有 `manifest.json`，先不要安装，保存报错给我。
如果找不到 PowerShell 7 或脚本被执行策略阻止，记录报错；不需要管理员权限或更改系统执行策略。

助手菜单操作：

| 输入 | 操作 | 何时运行 |
|---|---|---|
| 1 | 检查环境、校验 6 张 PNG | 安装前 |
| 2 | 保存原文件基线 | 安装前，退出游戏 |
| 3 | 采集变化和测试素材哈希 | 测试后，退出游戏 |
| 4 | 核对恢复后的文件 | 手动恢复后，退出游戏 |

重新打开助手后，操作 3／4 会要求粘贴原来的 `session-...` 路径。
脚本不会安装、删除或恢复游戏文件，也不会自动填写视觉通过。

## 四、安装这 6 张测试准星

1. 确认 KovaaK 已退出，打开 Windows 配置安装器。
2. 配置包目录选择 **包含 `crosshairs` 文件夹的解压根目录**，不要选到 `crosshairs` 里面。
3. 只选择 **准星**。不要选择主题、音效、完整设置、UI 或 Palette。
4. 核对清单：第一次安装应是 **6 张 `aimloom_test_...png` 新增文件**。
5. 如出现替换已有文件、修改设置或不认识的额外内容，先停止并截图。
6. 确认后安装，记录这次的批次／备份编号，并保存完成页截图。

文档与 `previews` 目录不属于游戏素材，会被跳过；SVG 也不要放进游戏准星目录。
如果之前已安装同一包，可能显示跳过已有文件，这不算一次新的安装验证；记录状态后再确认如何继续。

## 五、第一轮：逐张检查显示、透明度、形状和缩放

打开 KovaaK，进入同一个场景、使用同一种武器。在准星设置中手动选中测试 PNG。
文件名均以 `aimloom_test_` 开头，可用下面的案例 ID 对照文件名末尾。

截图中若 `TINT` 为绿色，先记录原来的着色设置；颜色核对时将 TINT 设为**白色（HEX `FFFFFF`）**，作为对照。绿色着色可能使彩色 PNG 变暗或变色，需要对照确认。当前截图中的 TINT 面板只有 RGB／HEX，没有透明度选项，不需要寻找透明度滑块。测试结束后恢复原 TINT。

选择准星后的菜单预览会随时间淡出（用户实测反馈）；不要用预览淡出来判断 PNG 的 alpha。

保存并关闭设置菜单后再拍场景截图；菜单预览不能代替实际场景的透明度和显示检查。

所有 PNG 都是 **128×128、导出 scale=1**。这与游戏自己的缩放值不同。
先统一使用游戏 scale=1（如果该选项可用）；否则记录实际值，并在六个案例间保持一致。

| 案例 ID | 应看到什么 | 重点观察 |
|---|---|---|
| `simple-cross` | 绿色四向十字，中央留空，无黑边 | 四条线是否居中、完整；背景是否透明 |
| `center-dot` | 白色中心小方点，没有四条线 | 小点是否可见、居中；周围有没有不该出现的方框 |
| `outlined-cross` | 青色十字，外侧有黑色描边 | 找较亮和较暗的位置看黑边；内部颜色是否异常变黑 |
| `half-alpha` | 半透明粉色十字 | 场景应能透过线条看见；不能出现整块黑底或白底 |
| `t-style` | 紫色左右、下方三条线和中心点，没有上方线 | T 型是否正确；这是 CS2 静态近似，不作原游戏精确对照 |
| `odd-thickness` | 很细的绿色十字 | 记录模糊、半像素边缘或不对称；先记录，不急着判定一定是导出错误 |

每一张按相同顺序做：

1. **显示**：能否找到、选中、看见。
2. **透明度**：在较亮／较暗的场景背景上观察，有没有不透明底框、黑边或异常颜色。
3. **形状**：对照上表；保存原始分辨率截图，不要缩放图片后再发。
4. **缩放**：记录当前值，改到另一个可用值观察变大／变小，再恢复统一测试值。把两个值记下来。

截图建议命名：`01_simple-cross_场景名_scale值.png`，其他案例按 ID 替换。
有问题时，同时截准星设置页和游戏画面。
小点或细线看不清时，先保存原始截图并标“受阻”；可以额外放大观察，但不要把放大结果当成 scale=1 的证据。

## 六、第二轮：检查退出、重开之后是否保持

对一个案例：

1. 选中该测试 PNG，记录文件名和游戏缩放。
2. 正常退出游戏，再重新打开，加载相同场景和武器。
3. 检查是否仍选中同一个 PNG、缩放是否保持，以及是否受场景／武器覆盖影响。
4. 保存重开后的截图，记录“保持”或实际变化。

**完整验收需要每个案例分别做这一轮。**
时间不够时，先做 `simple-cross` 即可；其他案例的“重开保持”写“未测”，不能一起填“通过”。
文件还在目录里，不等于游戏重开后仍选中了它。

完成显示和重启检查后，退出游戏，在助手中输入 **3**，标签可填 `after-restart`。保存生成的报告。

## 七、恢复原来的准星

1. 游戏内选回 `00_原设置.png` 中的原准星，并恢复原缩放和相关选项。
2. 正常退出游戏。
3. 在安装器里找到本次测试的批次，使用它的恢复／撤销操作，移除本批次新增的测试素材。
4. 在助手中输入 **4**，核对原有文件是否缺失、内容是否变化。
5. 再开游戏，确认原准星和原缩放正常；截图保存为 `99_恢复后.png`。

**不要清空整个 `crosshairs` 文件夹，不要批量删除不属于本次测试的文件。**
安装器备份保护的是素材安装；你在游戏里手动改的选中／缩放，要按原设置截图恢复。
遇到恢复冲突或失败，先停止并保存报错与批次编号，不要整目录覆盖。
只有实际完成这一节后，才把相应案例的“恢复”填为通过。

`matches_baseline` 只表示文件字节一致，不能证明游戏选中状态或视觉正确。
`needs_review` 表示存在差异，也可能包含正常的成绩变化；先查看报告，不要自动覆盖。
