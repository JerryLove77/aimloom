## 1. 第一版交付什么

交付一个离线 ZIP：**现成配置包 + 安装入口 + 恢复入口 + 简短说明**。用户无需安装 Node.js、Rust 或桌面配置管理器。

当前以 PowerShell 7+ 实现文件操作，用两个 `.cmd` 文件提供双击入口。主要交互采用中文控制台菜单；手动定位时打开系统文件夹选择器，打不开时允许输入路径。目标验收平台为 Windows 10/11。

```text
KovaaK-Config-v0.1.0/
├── 安装配置.cmd
├── 恢复配置.cmd
├── 使用说明.txt
├── scripts/
│   └── kvk-config.ps1
└── KVK Settings 2025/
    ├── Themes/
    ├── sounds/
    ├── crosshairs/
    ├── PrimaryUserSettings.json
    ├── UI.json
    └── Palette.ini
```

两个入口调用同一个脚本的安装／恢复模式，共用目录检查、备份和写入逻辑。默认读取随包目录，也允许用户选择相同结构的已解压配置包。脚本不读取 readme 中的指令执行操作。

仓库的音效和准星二进制被 `.gitignore` 排除：从 Git 拉下来的源码不等于完整发行包。打包时必须从实际素材目录收集文件，生成文件清单和 SHA-256；缺少发行清单要求的素材就停止打包。

## 2. 用户流程

### 安装

1. **找到配置包**：默认使用随包目录，展示名称和可安装内容。
2. **找到游戏**：检测常见 Steam 路径；没有结果则手选。有多个结果时列出选择，不取第一个直接写入。
3. **选择内容**：按主题、音效、准星、界面、配色、完整设置六类选择，不做逐文件向导。
4. **核对安装**：显示游戏目录、Palette 的独立目录、将新增／覆盖／跳过的文件数和备份位置；确认后执行。
5. **完成**：显示实际结果和备份编号，提供恢复入口，并说明哪些内容需要进入游戏选择。

### 恢复

1. 选择游戏安装位置对应的备份，默认展示最近一次安装记录。
2. 提供“撤销这次安装”与“恢复首次保护状态”两个选项，并列出影响范围。
3. 检查游戏已退出、备份完整、目标无冲突后执行，显示恢复／删除／失败清单。

“首次保护状态”指各文件第一次被本工具接管前的状态，不称为游戏出厂设置。以后首次安装其他类别时，只补充新接管路径的原始记录，已有原始记录永不改写。

## 3. 安装内容和生效含义

定义 `GameRoot` 为包含 `FPSAimTrainer` 子目录的安装根，例如 `D:\SteamLibrary\steamapps\common\FPSAimTrainer`；`GameData = GameRoot\FPSAimTrainer`。

| 包内内容 | 目标位置 | 默认 | 含义 |
|---|---|---|---|
| `Themes/*.json` | `GameData\Saved\SaveGames\Themes\` | 安装 | 增加可选主题，用户进游戏选择 |
| `sounds/*.ogg`、`*.wav` | `GameData\sounds\` | 安装 | 增加可选音效，用户进游戏绑定 |
| `crosshairs/*.png` | `GameData\crosshairs\` | 安装 | 增加可选准星，用户进游戏选择 |
| `UI.json` | `GameData\Saved\SaveGames\UI.json` | 不安装 | 整体替换界面配置 |
| `Palette.ini` | `%LOCALAPPDATA%\FPSAimTrainer\Saved\Config\WindowsNoEditor\Palette.ini` | 不安装 | 整体替换菜单／HUD 配色 |
| `PrimaryUserSettings.json` | `GameData\Saved\SaveGames\PrimaryUserSettings.json` | 不安装 | 整体替换该文件内的用户设置 |

只有包内存在的类别才可选。普通安装可以接受部分素材包；没有可安装内容则停止。临时文件、备份文件、ZIP 和未知文件不安装，核对页列出跳过项。

**复制素材不等于应用素材。** 第一版不生成主题补丁、不编辑音效字段、不自动切换准星；游戏内选用仍由用户完成。

完整设置选项显示明确说明：

> 使用包内 PrimaryUserSettings.json，覆盖当前灵敏度、DPI、FOV 等该文件中的设置。原文件会备份，可恢复。

用户明确开启该选项，并在最终清单确认后，才允许整体覆盖。UI 和 Palette 仍分别选择。“完整设置”仅指这份 JSON，不代表复制所有游戏存档；例如 `weaponsettings.ini` 不在本版范围内，也不承诺复刻作者所有武器音效。

这项决定有意调整旧总体设计中“永不写入手感设置”的规则：**v0.1.x 默认不动 Primary，但允许用户主动选择整文件替换**。旧桌面版的字段白名单逻辑不因此改变。

## 4. 文件处理规则

- **原样复制**：保留源文件名、主题内部 `themeName`、原始编码和字节，不重命名、不重新序列化 JSON。主题内部名与文件名不同不构成自动改写理由。
- **同名覆盖**：目标内容相同则跳过；内容不同则在清单中标记覆盖，备份后替换。不同名的用户文件保留，不清空整个目录。
- **预检在前**：检查所选文件可读、JSON 可解析为对象、目标路径有效以及备份可写。选中项有错误时停止，让用户取消该类别或修复后重试，不静默遗漏后继续安装设置。
- **固定范围**：仅处理上表中的文件和扩展名，素材目录只扫描一层；拒绝路径穿越、大小写冲突和指向范围外的链接／junction。文件夹名称相似不算游戏目录验证通过。
- **重复运行**：内容相同不写入、不产生空安装批次；需要替换时建立新备份。第一次原始备份不能被第二次安装覆盖。

游戏目录验证沿用仓库已知结构：检查内层 `Saved\SaveGames\PrimaryUserSettings.json` 和 `sounds` 目录。用户选到内层 `FPSAimTrainer` 时尝试规范化到外层，再验证；仍无法确认则停止。尚未生成设置文件时提示先运行并正常退出一次游戏。

v0.1.0 只检测常见安装路径，不全盘搜索。Palette 使用当前 Windows 用户的 LocalAppData，不使用游戏目录或脚本工作目录代替。

## 5. 备份、失败处理与恢复

### 备份范围

备份放在 `%LOCALAPPDATA%\KovaaKConfigInstaller\backups\<安装位置标识>\`，独立于游戏目录和解压目录。清单记录实际目标根路径；恢复前重新核对目标，不能把一套安装的备份应用到另一套目录。

只保护受影响的文件，不复制整个游戏。保存两种记录：

- **首次保护记录**：每个接管路径第一次写入前的字节，或“原先不存在”。永久保留。
- **本次安装备份**：本次所有待写路径的写入前状态，用于撤销本次安装。v0.1.x 不自动清理备份。

清单至少包含版本、批次编号、时间、安装位置、源包、选项、目标路径、原先是否存在、备份相对路径、原始与安装后 SHA-256，以及逐文件执行状态。备份文件和清单均写完、校验通过后才开始改游戏文件。

### 执行与中断

一次确认对应一个安装批次，素材和所选配置共同恢复。任何写入失败都停止后续写入，在游戏仍关闭且目标未被外部修改时，尝试撤销本批已执行的修改。

写入使用同目录唯一临时文件，落盘后替换，再读回校验。新增文件须独占创建；覆盖前重新核对旧文件 hash，避免在核对清单后覆盖别人刚做的修改。具体 Windows 替换行为必须在真机验证，不把跨文件操作称为一次原子提交。

同一安装位置仅允许一个脚本实例执行安装／恢复。开始及每次写入前检查 `FPSAimTrainer`、`FPSAimTrainer-Win64-Shipping` 进程；检测失败或游戏运行时停止，不强制关闭游戏。

持久记录批次状态：`prepared`、`applying`、`completed`、`rolled-back`、`recovery-required`。崩溃或关机留下未完成批次时，下次启动先引导恢复；根据清单、实际文件 hash 和执行记录核对，不能直接开始下一次安装，也不能仅凭“原先不存在”就删除文件。

权限不足时报告具体路径和原因，不自动提权、不修改系统执行策略。失败回滚也有可能失败：必须保留备份，并报告尚待恢复的文件，不能只显示“安装失败，已恢复”。

### 恢复规则

恢复前一次性校验全部备份文件、路径和当前目标状态；预检失败则不开始写入。

- 原先存在的文件：按备份字节恢复，恢复后校验 hash。
- 本次新增的文件：仅在执行记录与安装后 hash 能证明归属且当前内容未变化时删除；已不存在视为已恢复。
- 安装后被用户或游戏改动的文件：停止恢复并列出冲突。用户明确确认覆盖后，先另存这些当前文件再执行；自动失败回滚不能作出此选择。
- 无关文件与目录不清理。恢复中再遇游戏启动、文件变化或 I/O 错误时停止并记录进度，允许修复原因后重试。

恢复首次保护状态同样遵循这些规则，并明确列出全部接管路径。它不覆盖从未由工具处理过的用户文件。

## 6. 如何利用现有仓库

采用独立 PowerShell 入口，因此主要复用**已验证的规则、样本和测试场景**，不把 TypeScript 核心连同运行时一起分发。

本节记录设计时在 `b2099e7` 所在分支读取的背景代码；对其行为的描述属于当时的基线。2026-09-08 迁移到 `main` 的安装器直接使用 `scripts/installer/` 引擎，以下历史桌面编辑器代码不是运行依赖。

| 现有文件 | 可复用内容 | 本版需要调整的地方 |
|---|---|---|
| [配置包 readme](../KVK%20Settings%202025/readme.txt) | 素材与三个配置文件的落点 | 转成固定路径映射，不再让用户逐目录复制 |
| locate.ts（原 checkpoint：`b2099e7:packages/app/src/platform/locate.ts`）、paths.ts（原 checkpoint：`b2099e7:packages/app/src/platform/paths.ts`） | 常见路径和游戏目录结构 | 加入多结果选择、内外层归一化及独立 Palette 路径 |
| [importer.ts](../packages/core/src/pack/importer.ts) | 分类扫描、支持的素材扩展名 | `installPack` 目前直接复制，失败后保留部分结果；不能直接作为本版安装事务 |
| [backup.ts](../packages/core/src/safety/backup.ts) | 原始快照、不存在状态、恢复报告、新增文件 hash 收据 | 当前原始快照不自动扩充新路径，且有增量裁剪；本版需逐路径首次保护、覆盖文件校验和中断恢复 |
| [install-theme.ts](../packages/core/src/install/install-theme.ts) | 主题校验经验 | 当前会改内部名并重新序列化；本版原样复制，不直接采用此安装函数 |
| windows-verify.ps1（原 checkpoint：`b2099e7:scripts/windows-verify.ps1`） | PowerShell 入口、进程检查和字节采样经验 | 这是验证助手，不能当作可分发安装器；新入口不得硬编码开发者游戏路径 |
| [node-adapter.ts](../packages/core/src/platform/node-adapter.ts) | 文件操作与测试参考 | 默认进程检查返回 false，不能直接作为真实安装守卫 |
| Windows 验证记录（原 checkpoint：`b2099e7:docs/superpowers/notes/2026-09-03-windows-verification.md`）、音效格式证据（原 checkpoint：`b2099e7:docs/superpowers/notes/2026-09-05-b2-sound-format-verification.md`） | 目录、进程、编码和游戏回写行为 | 保留证据边界；既有记录不等于新脚本验收通过 |

新增代码建议集中在 `scripts/installer/`，测试放在其 `tests/` 下，发行打包入口放在同目录。既有 `packages/app`、`packages/core` 和 B1/B2 文档保留，不为脚本发行删除或重构它们。安装备份使用独立目录和格式，不读写旧桌面版备份。

## 7. 从桌面版设计中移出的内容

v0.1.x 不交付 React/Tauri 界面、Three.js 材质预览、试听播放器、素材浏览器、配置档保存／切换、主题字段编辑、音效绑定编辑、多音效序列化、Shoot 配置、联网下载或自动更新。

也不提供“保留灵敏度并自动合并整包设置”的第三种模式：它需要继续维护字段规则，与本版原样复制的范围不同。需要保留个人设置时，使用默认素材安装，再进游戏选用。

## 9. v0.1.0 验收标准

| 场景 | 必须观察到的结果 |
|---|---|
| 默认目录、非默认盘符、多个安装、选择内层目录 | 解析到正确目标；不确定时要求选择，不静默写错位置 |
| 只安装素材 | Primary、UI、Palette 的内容和修改时间均不变；游戏内能选到素材 |
| 选择 UI／Palette／完整设置 | 只覆盖明确选择的文件；字节与源一致；完整设置提示覆盖灵敏度等设置 |
| 同名不同内容、同名同内容、无关文件 | 分别备份覆盖、跳过、保留；不自动添加改名后缀 |
| UTF-8、BOM、UTF-16、中文及空格文件名 | 复制和恢复均保持字节；中文 PowerShell 脚本在 PowerShell 7+ 下正确读取 |
| 备份失败、源损坏、无权限、复制中途失败 | 备份前不写目标；部分写入能恢复，恢复失败准确列出剩余项 |
| 游戏运行、执行中启动、进程检测失败 | 停止写入；不会强行回滚到运行中的游戏 |
| 连续安装两次，再撤销第二次／恢复首次状态 | 分别回到第二次前／各接管文件首次修改前；原始备份未被改写 |
| 新增素材后恢复，或素材被外部修改 | 只删除有本批归属且未变化的新增文件；外部修改进入冲突处理 |
| 备份缺失／损坏、脚本中断、恢复中断、两个实例并发 | 无静默覆盖或误删除；未完成状态可识别、可重试；并发被阻止 |
| 使用最终 ZIP 在未安装开发环境的 Windows 上运行 | 双击入口可用，素材齐全，安装、游戏内检查和恢复全部走通 |

自动化在临时游戏目录验证文件行为与失败场景；最终 ZIP 还需 Windows 真机检查路径选择、进程识别、游戏读取和恢复。检查“文件已安装”与“游戏实际显示／播放”应分别记录，不能用合成素材测试代替实际播放验收。
