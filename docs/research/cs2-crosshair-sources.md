## Format and support boundary

The prefix is `CSGO-` for both CS:GO and CS2. Five groups of five case-sensitive characters encode an 18-byte payload with the 57-character alphabet `ABCDEFGHJKLMNOPQRSTUVWXYZabcdefhijkmnopqrstuvwxyz23456789`. Base-57 digits are stored least-significant first; the decoded integer is read as big-endian bytes. Byte 0 is the sum of bytes 1 through 17 modulo 256. The referenced encoder writes wire version 1 into byte 1.

| Byte | Decoded settings |
| --- | --- |
| 2 | Signed gap, divided by 10 |
| 3 | Outline thickness, divided by 2 |
| 4–7 | Red, green, blue, alpha |
| 8 | Low 3 bits: split distance; bit 7: follow recoil |
| 9 | Signed fixed crosshair gap, divided by 10 |
| 10 | Low 3 bits: color; bit 3: outline enabled; high nibble: inner split alpha divided by 10 |
| 11 | Low nibble: outer split alpha; high nibble: split size ratio; both divided by 10 |
| 12 | Thickness, divided by 10 |
| 13 | Bits 1–3: style; bits 4–7: center dot, weapon-dependent gap, alpha enabled, T style |
| 14 | Line length, divided by 10 |
| 15–17 | Zero in the reference encoder and every upstream fixture |

`parseCs2` accepts outer whitespace and retains the canonical, case-sensitive code. The 4096-character input limit applies before trimming. It rejects invalid characters/grouping, values exceeding 18 bytes, checksum failures, and unsupported versions. Unlike the upstream permissive `\w` expression, it accepts only the documented alphabet and exact separators.

Color values 6 and 7 and style values 6 and 7 have no supported interpretation and produce `UNSUPPORTED_FIELD`. Unknown bits 3–6 in byte 8, bit 0 in byte 13, or nonzero bytes 15–17 also produce `UNSUPPORTED_FIELD`. This conservative compatibility policy is based on the pinned encoder and fixtures; it does not assert that future game versions can never assign these positions. Recognizing an extension requires a new source and fixture before relaxing these checks.

Wire ranges are retained without guessed game UI limits: signed gaps are -12.8 to 12.7, line length/thickness are 0 to 25.5, outline thickness is 0 to 127.5, and nibble-based alpha/ratio fields reach 1.5. These capacities are not promises that the game renders or accepts every such value. Rendering must apply its own explicit output bounds and report approximations.

## Fixture provenance

`packages/crosshair/tests/fixtures/cs2.json` contains six literal code/settings pairs from the pinned upstream test file. They are external upstream test fixtures, not round trips generated by Aimloom's parser or an Aimloom encoder. No independent in-game capture provenance is claimed.

The tests additionally construct **synthetic** packed inputs to exercise corrupted checksums, future versions, unknown fields, wire bounds, and warning behavior. Those inputs are explicitly separated from the upstream fixture JSON.

## Static rendering limitations

The [CS2 client convar dump](https://cs2.poggu.me/dumped-data/convar-list/), inspected on the research date, describes styles 0, 1, and 3 as disabled; style 2 as dynamic split feedback; style 4 as static; and style 5 as legacy dynamic feedback. It describes `cl_fixedcrosshairgap` as applying to style 1, not as a general scoped-crosshair gap. This is community-published output from a game client, not a Valve SDK contract.

The parser preserves these settings and reports:

- `CS2_DISABLED_STYLE` for styles 0, 1, or 3.
- `CS2_DYNAMIC_STYLE` for styles 2 or 5.
- `CS2_FOLLOW_RECOIL` when recoil tracking is enabled.
- `CS2_WEAPON_GAP` when the gap depends on the equipped weapon.

A static image cannot reproduce movement, firing, recoil tracking, or weapon-dependent gap. This parser does not define pixel scaling, exact palette values, or a pixel-accurate game renderer. In particular, a 1080p scaling factor or a `gap + 4` formula was not established by the selected source. Visual fidelity still requires comparison against game captures.

Renderer projects considered but not copied:

- [girlglock/cs2-crosshair](https://github.com/girlglock/cs2-crosshair): GPL-3.0; its renderer implementation was not read or reused.
- [Skarbo/CSGOCrosshair](https://github.com/Skarbo/CSGOCrosshair): no repository license was found.
- [Kava4/cs2-crosshair-studio](https://github.com/Kava4/cs2-crosshair-studio): README labels it MIT and calls its preview approximate; no complete license file was found, so no implementation was reused.

## Verification

The first `npx vitest run --project crosshair cs2` run against a throwing parser stub produced **34 failed / 15 passed** tests. The external fixtures and supported behavior failed because parsing was absent; malformed-input checks already matched the stub's error type.

After implementation, the same focused command passed **49 / 49** tests, covering all six upstream fixtures, input normalization/limits, alphabet and case sensitivity, replay rejection, overflow, checksum, version, reserved fields, unknown style/color values, preserved wire bounds, and individual behavior warnings.

Review follow-up added six runtime type regression cases. Before the guard, these failed with native errors or the wrong structured code (**6 failed / 49 passed**). The parser now rejects non-string runtime values with `CrosshairError` / `INVALID_CODE` before inspecting length. User-facing errors and warnings use Simplified Chinese; machine-readable error/warning codes remain unchanged. The final focused suite passed **55 / 55** tests.
